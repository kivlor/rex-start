# rex-start

A minimal Linux client for [Rex](https://www.superlogical.com/rex), built from the
server's own public API. Goal: create and control sessions/panes on this
machine's Rex server and attach to them later from the Mac/iOS clients.

## Why

Rex ships no Linux GUI client (by design — nested windows fight tiling WMs),
but every server serves its full client protocol at `GET /llms.txt`. Sessions
live server-side, so anything this client creates is visible to Rex.app on
Mac/iOS over SSH/Tailscale, and vice versa.

## Status

- [x] **`crates/probe`** — headless proof of the full stack, no UI:
  control WS (`rex.control.v1`, API rev 19), `session.create` → `session.attach`,
  typed input via `com.superlogical.terminal.write`, data-ticket handshake
  (`rex.data.terminal.v1`, 17-byte binary HELLO → WELCOME with channel nonce),
  Ghostty snapshot + raw PTY stream to a file, `rex1` APC control messages
  (resize / theme / child_exited) decoded by nonce, screen read via
  `com.superlogical.terminal.format`. Leaves the session running on the server.
- [x] Render the stream through `libghostty` (`crates/rex-terminal`: restore
      snapshot, feed PTY bytes, apply rex1 messages by nonce; `replay` binary
      renders captured streams offline)
- [x] GPUI window (`crates/rex-app`): single pane → splits/zoom → session
      picker; server owns layout (`session_view_changed` → `session.view`),
      `session.new_split` / `session.zoom_block` bound to keys, closing the
      window leaves sessions running
- [x] Key input through `client.key` (so `init.lua` bindings see keys first;
      paste chunks sized by JSON-encoded length, under `limits.max_message_bytes`)
- [x] Resize ownership (`session.own_block`) — claim blocks, request grids,
      give blocks back on disown; the block follows its owner's grid
- [x] Reconnect/resume: the control connection reconnects with the latest
      welcome's `reconnect_token` (same client id, re-attach + re-own), and
      data streams RESUME with an exact byte count (`crates/rex-conn/examples/resume.rs`
      proves 3+ unclean-drop resumes and the ±1 REJECT reasons)

## Running the app

```sh
rex server start
WAYLAND_DISPLAY=wayland-0 cargo run -p rex-app -- -s <label>   # attach that session
WAYLAND_DISPLAY=wayland-0 cargo run -p rex-app -- --new-session  # make one and open it
REX_APP_DEBUG=1 … # protocol/render progress on stderr (frames, view refreshes)
```

Keys: `ctrl-alt-right` horizontal split, `ctrl-alt-down` vertical split,
`ctrl-alt-z` zoom/unzoom, `ctrl-alt-p` session picker (up/down, enter to
switch, `n` for a new session, esc to close). Splits and zoom go through
the server's ordered methods, one call at a time; layout geometry always
comes from the server. Closing the window only disconnects — sessions
and their programs keep running.

Building `rex-app` needs GPUI's Linux system libraries. On Fedora install
the development packages with
`sudo dnf install libxcb-devel libxkbcommon-devel libxkbcommon-x11-devel`
(the runtime loaders are usually already present). Build also requires
Zig 0.17, pinned via `mise` (see `mise.toml`). One more caveat: `libc` ≥ 0.2.190
removed `ENOATTR`, which breaks `xattr 0.2.3` (a GPUI dependency) —
the lockfile pins `libc 0.2.189` / `mio 1.2.4` until gpui updates.

## Running the probe

```sh
rex server start            # personal server, idempotent (sessions run as you)
cargo run -p probe --release -- --command pi --label pi-demo --seconds 10
rex ls                      # session stays alive after the probe exits
rex capture -s pi-demo      # view the pane from the CLI
rex kill pi-demo            # end it (kill takes labels positionally)
```

Other flags: `--socket` (default `$XDG_RUNTIME_DIR/rex/server.sock`),
`--seconds` (stream deadline, default 15).

## Replaying a captured stream

```sh
mise install                  # once: Zig 0.17 for ghostty-vt-sys (pinned in mise.toml)
cargo run -p rex-terminal --bin replay -- probe-stream-pi-demo.bin
# or force the channel nonce: ... -- probe-stream-X.bin --nonce 123456789
```

The nonce defaults to the one in the stream's first rex1 APC. The first build
of `ghostty-vt-sys` compiles libghostty-vt from its official source tarball
(takes a few minutes).

## Gotchas learned so far

- **Reconnect and resume**: the data byte count must be exact — the server
  REJECTs ±1 byte (0x03 fewer / 0x05 more) and that refusal ends the
  stream, forcing a start-over (new ticket + HELLO). One authoritative
  counter where frames are consumed (`rex_conn::StreamResume`), counting
  every processed binary payload across all connections, never the WELCOME.
  Keep the newest WELCOME token; never log it. A bare control client (not
  attached to anything) does not survive its drop — its token dies at
  once — so the reconnect path only matters for attached clients, which
  is every real client. Websocket pings arriving mid-RPC used to kill
  calls: `recv_json` skips control frames now.

- tungstenite needs `ws://` URIs and, for manually built `Request`s, the full
  upgrade header set (`Sec-WebSocket-Key` included) — and success is HTTP 101.
- Data tickets are base64url (no pad), 16 bytes, one use, 60s.
- `session.attach` is required before `data.connect`; a data connection is
  never compressed and must send HELLO within 5s.
- `com.superlogical.terminal.write` is a block method: args nest under `args`.
- The rex1 APC (`ESC _ rex1;<nonce>;<json> ESC \`) tells resize/theme/exit;
  the nonce comes from the data WELCOME and must be checked, because a
  program can print look-alikes. `rex-terminal` owns that parsing now.
- `ghostty-vt` is pinned to crates.io `0.9.0+ghostty-vt.1.0.1` (libghostty-vt
  1.0.1, MIT/Apache-2.0). The issue named 0.8.0, but 0.9.0 is the current
  release and builds fine here via its sys crate; it needs Zig 0.17 on PATH
  (or `mise exec`/`mise.toml`, which pins `zig = "0.17.1"`).
- `cargo clippy` catches a `never_loop` in probe's old control-message
  reader; keep the workspace clean before merging.
