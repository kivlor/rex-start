# rex-start

A minimal Linux client for [Rex](https://www.superlogical.com/rex), built from the
server's own public API. Goal: create and control sessions/panes on this
machine's Rex server and attach to them later from the Mac/iOS clients.

## Why

Rex ships no Linux GUI client (by design — nested windows fight tiling WMs),
but every server serves its full client protocol at `GET /llms.txt`. Sessions
live server-side, so anything this client creates is visible to Rex.app on
Mac/iOS over SSH/Tailscale, and vice versa.

## Status

- [x] **`crates/probe`** — headless proof of the full stack, no UI:
  control WS (`rex.control.v1`, API rev 19), `session.create` → `session.attach`,
  typed input via `com.superlogical.terminal.write`, data-ticket handshake
  (`rex.data.terminal.v1`, 17-byte binary HELLO → WELCOME with channel nonce),
  Ghostty snapshot + raw PTY stream to a file, `rex1` APC control messages
  (resize / theme / child_exited) decoded by nonce, screen read via
  `com.superlogical.terminal.format`. Leaves the session running on the server.
- [ ] Render the stream through `libghostty` (restore snapshot, feed PTY bytes)
- [ ] GPUI window: single pane → splits/zoom → session picker
- [ ] Key input through `client.key` (so `init.lua` bindings see keys first)
- [ ] Resize ownership (`session.own_block`) — claim blocks, request grids
- [ ] Reconnect/resume (control reconnect token; data RESUME with byte count)

## Running the probe

```sh
rex server start            # personal server, idempotent (sessions run as you)
cargo run --release -- --command pi --label pi-demo --seconds 10
rex ls                      # session stays alive after the probe exits
rex capture -s pi-demo      # view the pane from the CLI
rex kill pi-demo            # end it (kill takes labels positionally)
```

Other flags: `--socket` (default `$XDG_RUNTIME_DIR/rex/server.sock`),
`--seconds` (stream deadline, default 15).

## Reference

- `docs/API-rev19.md` — the protocol, regenerated by the server itself
  (`curl --unix-socket $XDG_RUNTIME_DIR/rex/server.sock http://rex/llms.txt`).
  Re-fetch after a rex upgrade; the server describes exactly what it speaks.
- Live method inspection: `rex api list / describe / call`.
- Prior art to crib from: `willothy/rex-linux` (Rust + GPUI + libghostty,
  same target stack), `shuv1337/rex-rune` + `a10y/rexrs` (typed protocol layer
  with revision negotiation), `zenodea/renux` (Zig/GTK4).

## Gotchas learned so far

- tungstenite needs `ws://` URIs and, for manually built `Request`s, the full
  upgrade header set (`Sec-WebSocket-Key` included) — and success is HTTP 101.
- Data tickets are base64url (no pad), 16 bytes, one use, 60s.
- `session.attach` is required before `data.connect`; a data connection is
  never compressed and must send HELLO within 5s.
- `com.superlogical.terminal.write` is a block method: args nest under `args`.
- The rex1 APC (`ESC _ rex1;<nonce>;<json> ESC \`) tells resize/theme/exit
  inside the PTY stream; check the nonce so program output can't spoof it.
